# Customer Churn Prediction

A machine learning project that predicts whether a telecom customer is likely to **churn** (leave the service), using the Telco Customer Churn dataset. The pipeline covers data cleaning, exploratory data analysis, feature engineering, comparison of six classification models, hyperparameter tuning, evaluation, and feature-importance analysis.

## Best Method

**Logistic Regression (tuned with `GridSearchCV`)** was selected as the best-performing model after comparing it against Decision Tree, Random Forest, Gradient Boosting, SVM, and KNN.

| Metric | Score |
|---|---|
| Accuracy | ≈ 0.82 |
| Precision | ≈ 0.68 |
| Recall | ≈ 0.60 |
| F1 Score | ≈ 0.64 |
| ROC-AUC | ≈ 0.75 |

**Why Logistic Regression won:**
- Best F1 / ROC-AUC balance among all six models on the held-out test set
- More stable across cross-validation folds than the tree-based models, which tended to overfit on this dataset size
- Fully interpretable — coefficients map directly to feature importance, which matters for a business use case like churn (stakeholders need to know *why*, not just *who*)
- Cheap to train and serve, making it easy to put behind an API

**Tuned hyperparameters** (via `GridSearchCV`, 5-fold CV, optimizing F1):
- `C`: regularization strength, searched over `[0.001, 0.01, 0.1, 1, 10, 100]`
- `penalty`: `l1` or `l2`
- `solver`: `liblinear`

*Exact scores vary slightly by run/seed — re-run the notebook end-to-end to reproduce.*

## Dataset

- **Source:** [Telco Customer Churn](https://www.kaggle.com/datasets/blastchar/telco-customer-churn) (IBM sample dataset, widely mirrored on Kaggle)
- **Rows:** ~7,000 customers
- **Target:** `Churn` (Yes / No)
- **Key features:** `tenure`, `MonthlyCharges`, `TotalCharges`, `Contract`, `InternetService`, `PaymentMethod`, plus demographic and service-usage fields

Place `WA_Fn-UseC_-Telco-Customer-Churn.csv` in the project root before running the notebook — it isn't bundled here.

## Pipeline Summary

1. **Data Cleaning** — coerce `TotalCharges` to numeric, impute missing values, drop `customerID`
2. **EDA** — churn distribution, contract/tenure/charges vs. churn, correlation heatmap
3. **Feature Engineering** — binary encoding (Yes/No, Male/Female), one-hot encoding for multi-category fields, feature scaling
4. **Model Training** — six classifiers trained and compared on accuracy, precision, recall, F1, and ROC-AUC
5. **Hyperparameter Tuning** — `GridSearchCV` on the top model (Logistic Regression)
6. **Evaluation** — confusion matrix, classification report, ROC curve, 5-fold cross-validation
7. **Feature Importance** — coefficient-based ranking of churn drivers
8. **Model Persistence** — trained model and scaler saved with `joblib`

## Key Findings

- Customers on **month-to-month contracts** churn far more than those on annual or two-year contracts.
- **Shorter-tenure** and **higher monthly-charge** customers are at higher churn risk.
- Customers **without tech support** and those paying by **electronic check** churn more.
- Gender has little to no relationship with churn.
